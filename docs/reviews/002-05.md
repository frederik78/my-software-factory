## Points d'attention
1. **CA-20 (le `case`)** : refusés `./..`, `a/./../b`, `a//..`, `../`, `a/../`, `/` ; acceptés à raison (noms légitimes ou littéraux inoffensifs) `..x`, `a/..b`, `...`, vide, `~`, `..\x`, `.`. Une valeur de fichier ne peut pas être multiligne (lecture ligne à ligne par awk) ; seule une variable d'environnement peut contenir un saut de ligne, mais c'est alors un nom de dossier littéral, non résolu comme `..` (« introuvable »). Aucune traversée. Aucune valeur évaluée ni recopiée dans le message [A01, A03]. Le contrôle précède le build et toute lecture du dossier.
2. **CA-25** : les quatre sources sont lues dans le dossier de travail avant le contrôle d'arbre propre ; un `.factory.conf` modifié non commité est refusé si fautif, sinon par « arbre non propre ». Le fichier local (ignoré par git) est contrôlé mais absent de `git archive HEAD`, donc ignoré dans l'extraction ; `FACTORY_DOSSIER_TESTS` est héritée.
3. **CA-21** : `.factory.conf:46` règle `DOSSIER_TESTS=factory/scripts/tests` ; `criteres-sans-test.sh 002-05` rend OK dans la suite (`run.sh:2009`, variables isolées par `env -u`).
4. **Choix du développeur, jugés bons** : refus sur les quatre sources même si une plus prioritaire les masque (RG-17 « quelle que soit sa source ») ; message identique, sans nommer la source ni la valeur ; variable définie mais vide = non définie.
