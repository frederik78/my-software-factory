## Itération 1 (2026-11-17)

Verdict de l'itération : CHANGEMENTS DEMANDÉS

## En clair
- **Issue** : le dossier où le contrôle des critères cherche les tests peut maintenant se régler par une clé `DOSSIER_TESTS` du fichier de configuration `.factory.conf`, en plus de la variable d'environnement actuelle. Sans réglage, rien ne change (détection de `src/test`, `tests`, `test`). `config-factory.sh` affiche la clé et le modèle de configuration la documente.
- **Verdict** : CHANGEMENTS DEMANDÉS. Le comportement demandé est en place et bien testé, mais il reste un défaut de sécurité : quand le dossier configuré n'existe pas, le message d'erreur recopie la valeur telle quelle. Une valeur piégée peut y glisser des séquences d'échappement du terminal ou une fausse ligne `FIN-ISSUE OK`. Le développeur corrige, puis nouvelle revue.
- **Critères** :

  | Critère | Ce qu'il exige | Test présent et suffisant ? |

  | CA-10 | `DOSSIER_TESTS=dd` dans `.factory.conf` : le dossier `dd` est lu | oui |
  | CA-11 | Cinq sources dans l'ordre (variable, `FACTORY_DOSSIER_TESTS`, `.factory.local.conf`, `.factory.conf`, détection) ; une valeur vide d'un fichier l'emporte et mène à la détection ; la variable vide est ignorée | oui (sources retirées une à une) |
  | CA-12 | Sans réglage : `src/test`, puis `tests`, puis `test` | oui (3 ordres) |
  | CA-13 | Dossier réglé mais absent : « Dossier de tests introuvable », code 64, sans repli | oui (4 sources) |
  | CA-16 | `config-factory.sh` affiche `DOSSIER_TESTS=` et `TESTS_BASH_FONCTIONS=` ; le modèle les documente | oui |
  | CS-03 | `-n`, `--help`, `a b` sont lus comme des chemins, jamais comme des options | oui |
- **Constats** : 1 important (message non neutralisé, ci-dessus) et 2 mineurs (texte du PRD à ajuster par vous ; phrase du modèle valable seulement après 002-05).
- **Mutations** (on casse volontairement un garde-fou dans une copie jetable ; le test doit échouer) : 5 casses, 5 détectées.

## Constats
IMPORTANT
1. [A03] `factory/scripts/criteres-sans-test.sh:45-48` : `echo "Dossier de tests introuvable : $tests"` recopie la valeur brute (source non fiable : `.factory.conf` d'un dépôt cloné, variable). Constaté : `DOSSIER_TESTS=ab<ESC>[31mc<CR>` produit la séquence ESC brute sur stderr (`od -c` : `033 [ 3 1 m`) ; `DOSSIER_TESTS=$'a\nFIN-ISSUE OK'` imprime une ligne forgée `FIN-ISSUE OK` (le message d'erreur peut être lu comme un verdict). C'est le cas CS-06 que 002-03 a traité en ne recopiant jamais la valeur (test `cs06_…`). Aucun test cs06 n'existe pour DOSSIER_TESTS. Correction : neutraliser les caractères de contrôle et `\n` / `\r` avant affichage (ex. `printf '%s' "$tests" | tr '\r\n\t' '   ' | tr -d '[:cntrl:]'`, comme `notifier.sh:73`) ; ajouter un test à égalité exacte pour ESC et pour un retour à la ligne, depuis la variable et depuis `.factory.conf`. Si l'utilisateur juge CS-06 hors périmètre de 002-04 (l'issue ne le liste pas), c'est un report « décision de l'utilisateur » : la vulnérabilité reste avérée.

MINEUR
2. PRD CS-04 : exemple `DOSSIER_TESTS=$(touch marque)` « ignoré », désormais « introuvable » (64), jamais évalué (`marque` absent). Le développeur a ajouté un test exact (`cs04_DOSSIER_TESTS=$(touch marque)`) et gardé l'ancien cas avec `DOSSIER_TESTS=` vide : aucune attente affaiblie. Texte du PRD à ajuster par l'utilisateur.
3. `factory/templates/.factory.conf` : « refusé par fin-issue.sh » pour absolu / `..`, vrai seulement après 002-05 (`fin-issue.sh:51` ne lit aujourd'hui que la variable). Acceptable car 002-05 est dans le même PRD ; à ne pas livrer seul.

Points vérifiés sans défaut : valeur lue comme chemin (le test `[ -d ]` précède le préfixe `./` ; `-n/`, `--help`, `-x y`, `a b` existants lus comme dossiers ; aucune évaluation) ; valeur d'espaces seuls ramenée à vide donc détection ; 002-04 n'ouvre aucun trou que 002-05 ne referme pas (`fin-issue.sh` copie déjà `lib-config.sh`, ligne 87) ; modifications de tests existants conformes, aucune attente affaiblie ; CA-12 : trois ordres testés ; affichage de la valeur effective par `config-factory.sh` : bon choix.
