## Constats

### BLOQUANT 1. [A03/A04] Les octets NUL sont supprimés avant la comparaison : une valeur falsifiée est acceptée
- Où : `factory/scripts/verdict-revue.sh:26`, `premiere="$(head -n 1 < "$fichier" | head -c 100)"`.
- Cause : une substitution de commande bash supprime les octets NUL (bash 3.2 comme bash 5).
- Reproduit sous `/bin/bash` 3.2.57 et `/opt/homebrew/bin/bash` : la première ligne `VERDICT: APPR\0OUVÉ` donne `APPROUVÉ`, code 0. `VERDICT:\0 APPROUVÉ` et `VERDICT: APPROUVÉ\0` aussi.
- Conséquence : RG-03 et A04 imposent une liste blanche stricte ; CS-03 cite les octets de contrôle. Une ligne non conforme est promue en `APPROUVÉ`.
- Test manquant : le seul fichier avec NUL (`binaire.md`, run.sh ~1650) a ses NUL sur la ligne 2.
- Correction suggérée : refuser tout octet NUL dans la première ligne (comparer la longueur en octets à celle de la valeur lue, ou `tr -d '\000'` contre l'original). Ajouter un test RED sur `VERDICT: APPR\0OUVÉ`.

### IMPORTANT 2. Test vacu : `cs03_erreur_sans_controle_*` ne peut jamais échouer
- Où : run.sh ~1659, `"$verdict" … 2>&1 >/dev/null | LC_ALL=C grep -q '[^[:print:]]' && ko … || ok …`.
- Cause : sous `set -o pipefail`, le script quitte en code 1 (INCONNU), donc le pipeline vaut 1 même quand `grep` trouve un caractère de contrôle ; `&& ko` ne se déclenche jamais. (Déduit de la lecture, mutation non lancée.)
- Correction : capturer la sortie d'erreur dans une variable, puis tester la variable.

### IMPORTANT 3. Couverture de test insuffisante
- `ca11_une_seule_ligne_sur_ligne_longue` (run.sh ~1630) lit `ancienne.md`, pas une ligne longue : le nom ne correspond pas au contenu.
- Lien symbolique, répertoire et fichier illisible non testés ; la mutation M5 (`-f` remplacé par `-e`) survit.
- Aucun test sans `-- ` pour un chemin hostile à la fois long et valide en préfixe.
- Les trois cas se comportent correctement à la main.

### MINEUR 4. Message
