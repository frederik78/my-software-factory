# Revue de l'issue 002-01 : Reconnaître un test bash

## Itération 1 (2026-11-16)

Verdict de l'itération : CHANGEMENTS DEMANDÉS

## En clair
- **Issue** : apprend au contrôle des critères (`criteres-sans-test.sh`) à reconnaître un test écrit en bash : un appel `verifier "ca10_x"` (guillemets, nom de critère au début) compte comme test du critère CA-10. Cela permet à la factory de contrôler ses propres issues.
- **Verdict** : CHANGEMENTS DEMANDÉS. Le code est correct sur l'essentiel, mais un test de sécurité ne prouve rien et une règle du PRD n'est pas respectée. Le développeur corrige, puis nouvelle revue.
- **Constats** :
  1. (IMPORTANT) Le test qui vérifie que le contrôle n'écrit aucun fichier (CS-05) ne peut pas échouer : il compare l'état du dossier après plusieurs essais, donc une écriture passe inaperçue. À refaire sur un dossier neuf.
  2. (IMPORTANT) Le PRD accepte les guillemets simples `'` et doubles `"`, le code seulement les doubles. À corriger.
  3. (IMPORTANT, reporté à 002-02) L'identifiant est cherché n'importe où dans le premier argument : `verifier "voir ca05"` couvrirait CA-05 à tort. Traité dans l'issue suivante.
  4 à 6. (MINEURS) Un commentaire mal placé, une fonction de test au nom piégeux, une casse sans effet.
- **Mutations** : le relecteur casse volontairement un garde-fou dans une copie jetable ; si les tests restent verts, ils ne protègent rien (casse « survivante »). Ici 5 casses sur 7 ont fait échouer un test (« tuées »), une est équivalente (sans effet), et une a survécu : celle du constat 1, ce qui prouve que le test CS-05 est trop faible.

  | Commentaires non ignorés | Un commentaire ne compte pas | tuée |
  | Fichiers autres que `.sh` lus | Seules les extensions prévues sont lues | tuée |

## Constats
IMPORTANT
1. `factory/scripts/tests/run.sh:~325-335` (CS-05) : l'assertion est vacueuse, car `avant` est pris après plusieurs appels du contrôle dans le même projet jetable.
   - Mutation M9 : ajouter `: > .trace` dans `noms_de_tests` (le contrôle écrit un fichier). Résultat : 16/0, donc survivante.

2. `factory/scripts/criteres-sans-test.sh:67` : la regex ne reconnaît que `"`. RG-01 du PRD dit « entre guillemets (`"` ou `'`) ».

   - Aucun CA de 002-01 ne l'exige, mais le texte de RG-01 est contredit. En-tête du script (l.10) : « guillemets doubles ».

MINEUR
4. `factory/scripts/criteres-sans-test.sh:45` : `fonctions_bash` est dans un bloc dont le commentaire parle de sed/LC_ALL. La placer près de `tests=` ou dans l'en-tête des clés rendrait 002-03 plus lisible. La liste codée en dur n'est pas détournable (constante littérale).
5. `factory/scripts/tests/run.sh:296-310` : le helper local `verdict_cas` redéfinit un nom de la liste par défaut, et ses appels sont eux-mêmes reconnus comme tests par le contrôle. Voulu mais piégeux : un commentaire l'expliquerait. Pas de cas d'auto-référence.
6. La mutation M6 (ligne de définition `verifier() {`) survit : mutation équivalente, la regex exige déjà un espace puis un guillemet. Non bloquant.
